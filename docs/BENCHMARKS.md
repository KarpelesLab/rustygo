# Benchmarks

Generated by `go run ./internal/cmd/bench` on linux/amd64 (go1.26.5-X:nodwarf5, best of 7 runs).
Both builds are native; gc is `go build` with default flags, rustygo is
`cargo build --release` on the emitted crate. M0 has no collector, so
rustygo's memory figures include everything it leaked. "+ shadow stack" is
the same program with GC root frames emitted (DESIGN §3): the cost the
collector's root bookkeeping will add, measured before the collector exists.
Runs of the three binaries are interleaved so machine noise affects them alike.

## Compile-time scaling

Generated programs of the M0 subset, built from scratch (runtime crate
already compiled):

| functions | Go lines | emitted Rust lines | cargo build (release) | ms per 1k Go lines |
|---:|---:|---:|---:|---:|
| 250 | 6255 | 38567 | 1.55 s | 247 |
| 1000 | 25005 | 154067 | 7.09 s | 283 |

The standard library of go1.26.5-X:nodwarf5 has 830154 non-blank lines of non-test Go
(GOROOT/src, excluding cmd/, testdata/ and _test.go). At the largest
program's rate that is about **235.34 s** of release build for the whole library.
This is linear extrapolation from generated code, so read it as an order of magnitude.
It is why M3 builds the stdlib once per Go version and target and caches it.
